# 预判规则（foresight）

目标：根据故事线和信号，提前判断接下来可能发生什么。判断要能验证、带概率、定期复盘，用实际的命中率说话。

## 一、预判的标准写法

每条预判必须同时满足下面几点，缺一项就不算预判，只算观点：

1. **可证伪**：结果只能是"发生"或"没发生"。不写「AI 会继续火热」这种无法验证的话。
2. **有截止日期**：例如「2026-12-31 前」。
3. **有概率**：用 10%–90% 之间的数字，不用「可能」「大概率」这类模糊词。
4. **有依据**：写明依据的故事线、日报编号、历史先例或基准率（类似的事过去发生的频率）。
5. **有验证方式**：到期时看什么数据、什么公告来判定。
6. **有风向标**：列出 1–3 个提前出现的信号。出现了就上调概率，没出现或出现反向信号就下调。

示例：

```text
【P-2026-10-28-01】Anthropic 在 2026-11-30 前完成纳斯达克上市
- 概率：75%
- 依据：S-1 已公开、目标 11 月 16 日当周（10-28 A3）；历史上 S-1 公开后 1 个月内上市的比例较高；风险是市场波动和监管问询
- 验证：纳斯达克代码 ANT 开始交易
- 风向标：路演定价区间公布（↑）；纳指单周跌超 5%（↓）；SEC 新一轮问询（↓）
- 故事线：🧵 anthropic-ipo
```

## 二、预判记录：data/calls.json

```json
{
  "id": "P-2026-10-28-01",
  "created": "2026-10-28",
  "thread": "anthropic-ipo",
  "statement": "Anthropic 在 2026-11-30 前完成纳斯达克上市",
  "probability": 0.75,
  "deadline": "2026-11-30",
  "basis": ["2026-10-28-A3"],
  "resolution_criteria": "纳斯达克代码 ANT 开始交易",
  "leading_indicators": ["路演定价区间公布", "纳指单周跌超 5%"],
  "updates": [{"date": "2026-11-05", "probability": 0.8, "reason": "路演启动"}],
  "status": "open",
  "outcome": null,
  "resolved_date": null,
  "review": null
}
```

- status：open / resolved / void（前提条件消失、无法判定时标 void，并写原因）。
- outcome：true / false。
- 概率调整写进 updates，不改原始概率，保留判断的变化轨迹。

## 三、在日报中的位置：「六、信号与预判」

- 信号与趋势：1–3 条分析，标注「分析」，写明依据的编号。
- 新增预判：每天 0–2 条。宁缺毋滥，没有足够依据就不写。
- 概率调整：已有预判的风向标出现时，列出「P-xxx 概率 60% → 70%，原因」。
- 到期结案：当天到期的预判，写结果和一句复盘。

## 四、复盘与校准

- **周报**：「上周预判复盘」，逐条写对了、错了还是未到期。错了要写原因：信息不够、推理有误，还是出现了意外事件。
- **月报**：「预判成绩单」：
  - 本月结案数量，命中率
  - Brier 分数（每条为 (概率 − 结果)²，结果发生记 1、没发生记 0，取平均；越低越好，一直填 50% 的得分是 0.25）
  - 校准情况：说 70% 的那一档，实际有没有七成左右发生
  - 本月最好和最差的一条预判，以及学到了什么
- 根据复盘结果更新本文件的「经验教训」一节，让以后的预判越来越准。

## 五、红线

- 预判只做行业和事件层面的判断，不写个股涨跌、目标价，不给任何买卖或仓位建议。
- 不预判伤亡、灾难这类人道事件的具体结果。
- 预判属于分析，必须和事实分开标注。
