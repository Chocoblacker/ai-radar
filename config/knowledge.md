# 沉淀规则（knowledge）

日报记录每天发生了什么，沉淀层负责把这些新闻串起来，回答这件事是怎么一步步走到今天的、接下来要看什么。沉淀分三种：故事线、概念卡、周报和月报。

## 一、故事线 threads/

### 什么算一条故事线
- 跨越多天、还在继续发展的事件或主题，例如 IPO 进程、央行利率路径、地区冲突与油价、产业链短缺、一类安全事件、监管博弈。
- 一条新闻如果以后大概率还会有下文，就挂到已有的故事线上，或者新开一条。
- 同时保持活跃的故事线控制在 8–15 条，太细碎的合并。

### 文件
- `threads/<slug>.md`：每条故事线一个页面，slug 用英文短横线，例如 `anthropic-ipo`。
- `threads/index.md`：总览表，列出名称、状态、开始日期、最近更新、下一个验证点、关联的预判。
- `data/threads.json`：结构化数据，包括 id、title、status、started、last_update、related_items（日报编号列表）、next_checkpoint、related_threads、calls（预判 id 列表）。

### 页面结构
```markdown
# 故事线名称
状态：进行中 / 休眠 / 已结案 · 开始：YYYY-MM-DD · 最近更新：YYYY-MM-DD
下一个验证点：日期 + 事件

## 一句话现状
## 来龙去脉（200 字以内，每次更新时重写，保持最新）
## 时间线
- MM-DD 事件（[YYYY-MM-DD A3](../daily/YYYY/MM/YYYY-MM-DD.md)）
## 关键数字（附来源和日期，数字更新时保留旧值并注明变化）
## 各方观点（支持 / 反对，附来源）
## 还没有答案的问题
## 情景推演
- 基准情景（概率 %）：……；触发信号：……
- 乐观情景（概率 %）：……；触发信号：……
- 悲观情景（概率 %）：……；触发信号：……
  三个情景的概率加起来是 100%
## 关联预判（P-xxx）
## 相关故事线
```

### 生命周期
- 每天生成日报时，有新进展的故事线同步更新页面和 threads.json。
- 超过 21 天没有新进展，状态标为「休眠」；以后有新进展可以重新激活。
- 事件结束时标为「已结案」，写 200 字以内的结案总结，并回顾当初的情景推演哪一个说中了。

### 在日报中：「五、故事线追踪」
- 每天列 3–5 条当天有进展的故事线，每条一行：
  `🧵 **名称**（第 N 天）上回：…… → 今天：……（编号）→ 接下来看：……`
- 正式新闻如果属于某条故事线，在条目末尾标注 `🧵 名称`。
- 「🔄更新」类条目的前情只写一句，链接到故事线页面。

## 二、概念卡 glossary/

- 反复出现的专业概念，第一次出现时写一张卡片：`glossary/<slug>.md`。例如 CoWoS、HBM、FOMC、ATM 增发、世界模型、供应链攻击。
- 内容：是什么（两三句大白话）、为什么重要、常见误区、相关故事线、英文表达。
- 日报里只写一行「📘 概念卡：CoWoS」并附链接，不重复解释。
- `glossary/index.md` 按领域列出全部卡片。

## 三、周报与月报

### 周报 weekly/YYYY-Www.md（每周日）
1. 本周 Top 10（保留）
2. 故事线进展：每条活跃故事线本周的变化，新开的线，休眠或结案的线
3. 预判复盘：见 `config/foresight.md`
4. 下周看点：来自故事线的验证点和预判的到期日

### 月报 monthly/YYYY-MM.md（每月 1 日）
1. 本月最重要的 5 条故事线，每条 200 字讲清来龙去脉和现在走到哪一步
2. 本月的大趋势判断：三五句话
3. 预判成绩单（见 `config/foresight.md`）
4. 下月关键日程
- README 首页显示最新月报的入口和活跃故事线的列表。

## 四、原则
- 沉淀层只用已经在日报里出现、带编号和来源的事实。新事实先进日报，再进故事线。
- 故事线页面写的是现状，不是新闻堆砌：时间线可以长，但「一句话现状」和「来龙去脉」要短，并且每次更新时重写。
