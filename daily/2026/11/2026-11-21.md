### Agent 与工具

**【A5】 OpenAI 披露 Performance Factory：Codex Agent 自动查 ChatGPT 性能回退**
- 要点：OpenAI 经 VentureBeat 独家工程报告披露内部系统 Performance Factory：告警触发后 Codex Agent 查指标、代码变更与日志定根因，另一 Codex 会话以全新上下文做对抗性复核（约 25% 的诊断被打回），通过后起草修复 PR 由工程师决定是否合并，上线后另有 Agent 核查恢复情况。3 个多月累计 1700 多次调查、600 多例找到根因（日均约 17 次）；600 多例中约 400 例进入修复提案，最终原样落地的 Codex 撰写 PR 约 15 个、另约 50 个修复受 Agent 建议影响或一致；人工抽查 100 例根因建议，70% 判定准确。
- 为什么重要：Agent 从「写代码」走向「接管运维值班」的最具体大厂实证——多 Agent 分工（调查/对抗复核/验证）加人终审的模式可直接复用到运维自动化；同时 15/400 的落地率也诚实地标出了 Agent 自动修 bug 的当前天花板。
- 来源：[VentureBeat 独家报道](https://venturebeat.com/orchestration/exclusive-openai-reveals-performance-factory-a-codex-powered-software-optimization-system-that-keeps-chatgpt-fast) · 交叉来源：OpenAI Developers LinkedIn 帖、多家跟进报道

### 安全与监管

**【A9】 Google 公开「Mirror Dimension」：造了一个假互联网来训练和测试 Chrome 浏览 Agent**
- 要点：Google Chrome AI 安全团队 11 月 19 日在官方安全博客披露 Mirror Dimension：一个与真实网络隔离的合成互联网，内含数千个模拟网站（社交、电商、银行面板等），Agent 在无头 Chrome + gVisor 沙箱中访问，本地代理拦截流量并伪造 TLS 证书，使 Agent 以为在访问真实网址。团队用多 Agent 搭建网站、以隐藏指令测试间接提示词注入；自动化红队流程让每名安全工程师每天生成 1000 多个攻击测试用例，约为人工的 30 倍。
- 为什么重要：浏览器厂商首次系统披露用「合成互联网」做 Agent 安全压测的方法论，直接回应 2026 年 Agent 提示词注入高发的问题。
- 来源：[Google 安全博客](https://blog.google/security/mirror-dimension-for-agents/) · 交叉来源：Digital Trends、Wired
- 可信度：✅已证实（官方博客）

**【A10】 微软 Agent Framework PyPI 投毒事件：三仓库仍 404、微软仍无官方说明**
- 要点：11 月 17 日，微软 Agent Framework 的两个恶意版本 1.26.1 / 1.26.2 在 PyPI 上线约 40 分钟后被撤下，.pth 文件使凭证窃取器随每次 Python 启动运行，窃取 Azure、DevOps、GitHub Actions 凭证及 .env 文件；Wiz 仅确认 3 起真实受害数据外泄。11 月 20 日的新情况：微软的 microsoft/agent-framework、microsoft/onnxruntime、microsoft/onnxruntime-genai 三个 GitHub 仓库仍返回 404，微软截至当日仍未发布官方说明或根因公告；Wiz 判断攻击者疑似盗用了微软内部发布管道 ESRP 的客户端证书与私钥，但证书如何泄露仍未知。
- 为什么重要：针对 AI Agent 开发工具链的供应链攻击：一个被广泛使用的官方 Agent SDK 包被投毒，装过 1.26.1 / 1.26.2 的环境须假定全部凭证已泄露并轮换；根因指向签名发布管道而非源码仓库，暴露了证书发布环节的薄弱点。
- 来源：[Wiz 博客](https://www.wiz.io/blog/malicious-version-of-microsofts-agent-framework-published-to-pypi) · 交叉来源：Corgea 研究汇总、PyPA 公告
- 可信度：🟡多方报道（事件本身经 Wiz + PyPA 确认；「盗用 ESRP 证书」仅为 Wiz 的判断，微软未确认）
