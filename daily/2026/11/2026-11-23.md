### Agent 与工具

**【A3】 OpenRouter 下架 3 家推理服务商，125 个端点取消零数据保留资格**
- 要点：OpenRouter 11 月 22 日官方公告称，已下架 3 家推理服务商、将 125 个端点移出零数据保留（ZDR）资格，并通知了所有可能受影响的客户。背景是安全公司 Dragos 11 月 19 日公布的金丝雀研究：7–11 月间向各 AI 服务发送约 200 万条带唯一链接和假凭证的提示，发现至少 3 家服务商的数据遭窃取，部分被标为 ZDR 的请求也被读取、留存甚至转给第三方。OpenRouter 称自身未被攻破；被下架的 3 家未具名。
- 为什么重要：这是"ZDR 只是标签、不是保证"首次在网关层面落到处罚动作上，直接动摇用户把敏感提示交给第三方推理托管的信任假设。
- 来源：[OpenRouter 官方公告](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/) · 交叉来源：The Hacker News、Dragos 研究
- 可信度：✅已证实（官方一手发布；Dragos 研究细节为该公司披露）
- 🧵 Agent 安全

**【A4】 Together AI 披露：AI 编程 Agent 把凭证提交进公开仓库，致 6–7 月客户提示样本泄露**
- 要点：Together AI 官方安全公告（11 月 21 日发布、11 月 22 日更新）称，开发公开 GitHub 仓库 xorl 时，一个 AI 编程 Agent 提交了可访问私有 Hugging Face 仓库的凭证；未授权方在凭证暴露期间下载了其中存放的客户提示样本。样本来自 MiniMax M3、GLM-5.2、Kimi K2.6 的请求，主要集中在 6 月 24 日、7 月 4 日、7 月 8 日、7 月 14 日共 4 天；对方还在样本中搜索并测试其他服务凭证，其中 5 个是 Dragos 金丝雀实验的假凭证。Together 已将 ZDR 改为新账户默认，并收紧凭证与 Agent 开发流程。
- 为什么重要：这是一起根因就是"Agent 自主提交了密钥"的泄露事件——不是提示注入、不是模型越狱，而是 Agent 在正常开发流程里做了人类不会做的事且无人复核，直接对应 Agent 落地时的代码提交管控缺口。
- 来源：[Together AI 官方安全公告](https://www.together.ai/blog/security-event-prompt-leakage-for-requests-in-june-and-july-of-2026) · 交叉来源：The Hacker News、Unite.ai
- 可信度：✅已证实（官方一手发布）
- 🧵 Agent 安全

**【A5】 开源浏览器 Agent browser-use 发布 1.0.8，补无头机扫码登录与密码不回显**
- 要点：browser-use 1.0.8 于 11 月 22 日发布：无 API key 时，SSH 或无头机上的运行会打印链接和验证码、可在任意设备上批准后继续；评判器改为同一 run 内多一轮，复用提供方缓存、不再为评判轨迹重复计费；`bu.type` 不再打印密码字段的值；网关调用的输出 token 预留从 32768 改为 16384，避免小额余额中途被拒。
- 为什么重要：无头/SSH 场景的扫码登录与密码不回显是 Agent 在服务器上跑时的两个实际安全与可用性改进，与运维直接相关。
- 来源：[browser-use GitHub Releases](https://github.com/browser-use/browser-use/releases) · 交叉来源：whatsnew.fyi、多家聚合记录
- 可信度：✅已证实（官方发布记录）

### 安全

**【A9】 OpenAI 大面积故障 3.5 小时：数据库例行维护拖垮认证层，请求失败率峰值 75%**
- 要点：美国时间 11 月 21 日 13:48–17:21（北京时间 11 月 22 日 05:48–09:21），OpenAI 的 ChatGPT 与 API 请求失败率峰值达 75%，持续 211 分钟；原因是 Primary API 服务所用的 PostgresDB 例行维护导致两个读副本同时故障，该服务承担全栈用户认证与服务间认证，故障波及 Chat Completions、Fine-tuning、Embeddings、Images、登录、搜索、文件上传、语音模式等。OpenAI 当日在状态页发布事后说明，已暂停同类维护、调整连接池配置并上线可按比例切走副本流量的开关。
- 为什么重要：一次常规数据库维护击穿双副本冗余、拖垮整个认证层，是今年最严重的单点故障案例之一，直接指向单供应商 Agent 栈的脆弱性；对运维读者有直接借鉴意义。
- 来源：[AI Weekly（引述 OpenAI 状态页事后说明）](https://aiweekly.co/alerts/openai-postgres-replica-failure-peaked-api-chatgpt-errors-at-75) · 交叉来源：Dev.to 日报、LexxWire
- 可信度：🟡多方报道（多家二手报道口径一致，均引述 OpenAI 状态页原文；未直接核验状态页）
